1. Project Overview & File Hierarchy

Section 1.0 — Architecture & Structure

The objective of this project is to architect an interactive Command Line Interface (CLI) Crossword Puzzle game developed in modern C++17. The program dynamically loads an English vocabulary corpus, coordinates word overlaps using backtracking and priority queues, guarantees single-component puzzle topology using Graph Breadth-First Search (BFS), and stores high-scores in a dynamic Binary Search Tree.

Section 3.0 — Visual Data Structure Diagrams

3.1 The Reference Counter Matrix: uses[15][15] (grid.h)

In a crossword, when two words intersect (e.g. HOUSE across and WATER down), cell $(4, 4)$ holds 'E'. If HOUSE is removed during backtracking, blindly clearing the cell to empty corrupts WATER. The uses[r][c] counter ensures characters are only erased when usage hits zero.

5. Engineering Impediments & Solutions

Section 5.0 — Problem Solving & Debugging
Impediment 1: Shared Cell Deletion during Backtracking

Symptom: When two words intersect (e.g., APPLE across and PLANT down sharing 'P'), removing APPLE wiped the cell to empty, corrupting PLANT.
Fix: Implemented the uses[15][15] matrix. Each placement increments usage; backtracking decrements usage. Characters are only cleared when uses[r][c] == 0.

Impediment 2: Parallel Flank Collisions

Symptom: Candidate words were placed adjacent to one another (e.g., CAT on row 1, DOG on row 2 right beneath it), violating crossword rules.
Fix: Enforced perpendicular flank validation in grid.canPlace() ensuring lateral cells are empty unless forming a legal crossing.

Impediment 3: Disconnected Island Crosswords

Symptom: The generator placed all words legally according to local rules, but generated 2 or 3 floating, disconnected mini-puzzles on the board.
Fix: Built an Adjacency List representing intersections between words and evaluated it using a BFS queue. If visitedCount < totalWords, the layout is discarded and regenerated.

Impediment 4: Windows Console Screen Redraw Scrolling

Symptom: Using standard ANSI \033[2J failed to wipe the command buffer in Windows CMD/PowerShell, causing the board to reprint below past turns in an endless scroll.
Fix: Implemented direct Win32 API console clearing via FillConsoleOutputCharacter, FillConsoleOutputAttribute, and SetConsoleCursorPosition(hConsole, {0,0}) with an automated std::system("cls") fallback.

6. Comprehensive Viva Voce Cheat Sheet

Section 6.0 — Viva Examination Defense

6.1 Standard Technical Questions & Model Responses

Q1: Why did you choose an Adjacency List over an Adjacency Matrix for the word graph?
Answer: Crosswords are sparse graphs ($V \approx 8$ words and $E \le 12$ crossings). An adjacency matrix would allocate $V^2 = 64$ entries filled mostly with zeroes. An adjacency list requires only $O(V + E)$ memory and allows BFS to inspect neighbors in $O(\text{deg}(v))$ time rather than scanning an entire matrix row in $O(V)$ time.

Q2: Why is a Max-Heap utilized in the generator instead of a sorted array?
Answer: For every word, hundreds of candidate coordinates and orientations are evaluated. Storing candidates in a Max-Heap allows $O(\log K)$ insertion and $O(\log K)$ extraction of the placement with the highest letter crossings, ensuring the generator greedily creates dense, well-interlocked puzzles.

Q3: How does Reverse Inorder Traversal in a BST work?
Answer: Standard inorder traversal visits Left -> Root -> Right, outputting data in ascending order. Reverse inorder traverses Right -> Root -> Left. Because the right subtree holds higher values, it visits highest scores first, generating a descending leaderboard without needing a separate sorting algorithm.

Q4: Why is Postorder Traversal necessary when destructing a BST?
Answer: In C++, deallocating a parent node before its children results in dangling pointers and memory leaks. Postorder traversal (Left -> Right -> Root) ensures both child subtrees are completely freed before the parent node is deleted.

Q5: What is the worst-case time complexity of BST insertion, and how is it mitigated in production?
Answer: If scores are inserted in already sorted order, the BST degenerates into a linear linked list with worst-case height $O(M)$ and insertion time $O(M)$. In commercial systems, an AVL Tree or Red-Black Tree uses tree rotations to maintain balanced height $O(\log M)$.

Q6: How does your grid handle memory and coordinate lookups?
Answer: The grid is stored as a flat 2D array of static dimensions $15 \times 15$. Lookups board[r][c] operate in $O(1)$ constant time with zero dynamic allocation overhead.
