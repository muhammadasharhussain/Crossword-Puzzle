Interactive Printable & Editable DSA Project Report

1. General Overview & DSA Matrix

Section 1.0 — Architecture

The objective of this project is to architect an interactive Command Line Interface (CLI) Crossword Puzzle game developed in modern C++17. The program dynamically generates a valid, connected crossword from an English vocabulary corpus, coordinates word overlaps, computes candidate coordinates using Priority Queues, validates topology using Graph traversals, and stores high-scores in a dynamic Binary Search Tree.

2.2 Runtime Execution Flow

When executed, the program initiates execution in main.cpp, configuring the Windows Console to enable Virtual Terminal Processing. The user selects a puzzle difficulty which governs the target word count. The CrosswordGenerator selects anchor words, evaluates placements with a Max-Heap, commits them to the 2D grid, and confirms full grid connectedness via Graph BFS. The gameplay loop updates the board in-place using native Windows console clearing on every user turn.

Zero Hash-Map Guarantee In strict compliance with the CT159 course outline up to Week 13, all word lookups, dictionaries, and graph representations completely avoid std::unordered_map and hashing techniques, relying exclusively on Sequential Vectors, Pointer Trees, Heaps, and Queues.

3. Core Data Structures: Grid & Generator

Section 3.0 — Code Snippets & Logic

3.1 Grid Reference Counting & Cell Validation (grid.h)

The crossword grid requires dynamic letter sharing between perpendicular intersecting words. If a simple character matrix is used, backtracking or removal of one word inadvertently deletes letters shared by intersecting words. We resolved this via parallel reference counting matrix uses[15][15].

src/grid.h — Reference Counting Implementation
void place(const std::string& word, int row, int col, Direction dir) {
    int len = static_cast<int>(word.length());
    for (int i = 0; i < len; ++i) {
        int r = (dir == ACROSS) ? row : row + i;
        int c = (dir == ACROSS) ? col + i : col;
        board[r][c] = word[i];
        uses[r][c]++; // Reference count increment
    }
}

void remove(const std::string& word, int row, int col, Direction dir) {
    int len = static_cast<int>(word.length());
    for (int i = 0; i < len; ++i) {
        int r = (dir == ACROSS) ? row : row + i;
        int c = (dir == ACROSS) ? col + i : col;
        uses[r][c]--; // Decrement counter
        if (uses[r][c] <= 0) {
            board[r][c] = ' '; // Only clear when no other word uses this cell
            uses[r][c] = 0;
        }
    }
}

3.2 Candidate Intersection Ranking via Max-Heap (generator.h)

Rather than picking random placements or doing an exhaustive exponential brute-force search, every valid coordinate is evaluated and inserted into a Max-Heap (Priority Queue) sorted by crossing frequency.

src/generator.h & src/types.h — Max-Heap Placement Logic
// Overloaded comparator for Max-Heap priority
struct CandidatePlacement {
    int row, col;
    Direction dir;
    int crossings;
    bool operator<(const CandidatePlacement& other) const {
        return crossings < other.crossings; // Higher crossings = Top of Heap
    }
};

// In CrosswordGenerator::generate():
std::priority_queue<CandidatePlacement> maxHeap;
for (int r = 0; r < GRID_SIZE; ++r) {
    for (int c = 0; c < GRID_SIZE; ++c) {
        for (Direction dir : {ACROSS, DOWN}) {
            if (grid.canPlace(candidateWord, r, c, dir, false)) {
                int crossings = grid.countCrossings(candidateWord, r, c, dir);
                maxHeap.push({r, c, dir, crossings});
            }
        }
    }
}
if (!maxHeap.empty()) {
    CandidatePlacement best = maxHeap.top(); // O(1) retrieval of best crossing
    grid.place(candidateWord, best.row, best.col, best.dir);
}

4. Graph BFS & BST Leaderboard

Section 4.0 — Traversal Mechanics

4.1 Word Intersection Graph & BFS Connectivity (graph.h)

A crossword must be fully interconnected. If words form separate disconnected groups on the grid, the crossword is invalid. We model words as vertices ($0 \dots V-1$) and intersections as edges, verifying single-component connectivity using Breadth-First Search (BFS) with a std::queue.

src/graph.h — BFS Traversal Algorithm
bool isConnected() const {
    if (numVertices <= 1) return true;
    std::vector<bool> visited(numVertices, false);
    std::queue<int> q; // Week 5: FIFO Queue ADT

    visited[0] = true;
    q.push(0);
    int visitedCount = 0;

    while (!q.empty()) {
        int u = q.front();
        q.pop();
        visitedCount++;

        for (int neighbor : adjList[u]) {
            if (!visited[neighbor]) {
                visited[neighbor] = true;
                q.push(neighbor);
            }
        }
    }
    return visitedCount == numVertices; // Guaranteed 1 connected component
}

4.2 Leaderboard Binary Search Tree (bst.h)

The high-score leaderboard uses a custom dynamic node-based Binary Search Tree. Scores are inserted in $O(\log M)$ average time. To display rankings in descending order without an external sorting pass, we utilize Reverse Inorder Traversal (Right $\to$ Root $\to$ Left). Safe tree memory deallocation is guaranteed via Postorder Traversal.

src/bst.h — Reverse Inorder & Postorder Methods
// Reverse Inorder: Right -> Root -> Left (Prints Highest Scores First)
void reverseInorder(BSTNode* node, int& rank, int maxEntries) const {
    if (!node || rank > maxEntries) return;
    reverseInorder(node->right, rank, maxEntries); // Visit higher scores
    if (rank <= maxEntries) {
        std::cout << rank << ". " << node->data.playerName 
                  << " - " << node->data.score << " pts\n";
        rank++;
    }
    reverseInorder(node->left, rank, maxEntries);  // Visit lower scores
}

// Postorder Traversal: Left -> Right -> Root (Prevents Memory Leaks)
void destroyTree(BSTNode* node) {
    if (!node) return;
    destroyTree(node->left);
    destroyTree(node->right);
    delete node; // Deletes parent only after children are deallocated
}
